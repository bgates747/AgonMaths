# Development log — 2026-08-09

## Pingo3D community API roundup

The Agon project guidance under `agon-dev-env/codex/` was reviewed before the
roundup. This pass inventories and consolidates proven code; it deliberately
does not optimize or rewrite arithmetic. Native ADL-width operations remain in
place when they are part of a documented local contract.

The search followed direct `p3d_*` symbols, exact source/table blobs, renamed
multiply bodies, project documentation, and Git provenance across the owned
Agon repositories. The only direct P3D consumers outside AgonMaths are
`pingoasm` and `pingo_terrain`. The Wolf breadcrumb resolves to the historical
`Wolf3dOrig` checkout; the canonical `AgonWolf3D` checkout contains no P3D/W3D
copy or newer counterpart. An older `agon-utils` example is the multiply
donor. No other owned checkout produced a P3D copy or distinctive transform
implementation.

### Pingo terrain

Four physical source/table pairs serve eleven entry applications: Berkeley
flight, its triangular and dither variants, Berkeley camera survey, Campanile
probe, regional camera survey, terrain-manager survey and its current natural
variant, Berkeley FDM, KOAK streamed flight, and KOAK family-LOD flight.

Every table is byte-identical to AgonMaths. The FDM core is also exact. The
other three core copies differ by one comment on the same instruction:

```asm
ld hl,(iy+6) ; ADL24 OK: work-frame bytes 6..8 are a staged 24-bit magnitude
```

The load is intentionally 24-bit: the preceding stores stage the bounded
`x^2+z^2` radicand in bytes 6..8 for `p3d_lookat_isqrt24`. The downstream
comment was brought back; no instruction was changed.

Eleven byte-identical application-local `sync_camera_state` routines expose a
real API pressure point. They send retained camera position and rotation using
application `scdabs`/`scrabs` helpers. The core has object packet builders and
`p3d_object_sync16`, but no camera builder or sync routine. The historical
2026-07-30 log claimed `p3d_camera_sync16`; no such label was implemented or
tested. Normative documentation now states the actual boundary, and
`P3D-API-1` names the exact publication decision.

The flight project contains genuine additions beyond Earth Party, Anim, and
the movement demos. The reusable caller-owned subset is now vendored as the
optional `3d_fsim.inc`, with SHA-256
`72a9c488b5df41873253413292da9fb760716d0cac97d91db57f4868f64386a3`.
It is a source-faithful API extraction from pingo_terrain commit
`58f0b61734f35965752833c9f74b34cdd55ed296`; no arithmetic was optimized.

The four F2 leaf bodies for rate damping, rate clamping, signed-Q8 drag, and
velocity clamping are instruction-for-instruction donor bodies apart from
namespacing. The axis-moment wrapper retains the donor control flow. The other
entries deliberately adapt only ownership and ABI:

- the qualified transpose byte mapping now receives distinct source and
  destination matrix pointers;
- the camera-offset matrix/translation composition now receives a writable
  point and retained object pointer and documents its partial failure state;
- the backdrop's `asin(-r1c2)`/`atan2(r1c0,r1c1)` extraction now returns pitch
  and roll in registers, without viewport or drawing policy; and
- the static, immediately-sent packet clients now build into caller-owned
  buffers and leave transport to the integration layer.

The last group covers experimental Pingo subcommands 51 (object active), 52
(signed-24 object translation), and 53 (projection far). Command 51 comes from
the canonical `p3dm-loader.inc` lines 857–878 block, whose SHA-256 is
`df29b55865b798b202477e92d10ef28f7b3316138c1965efe7cd43f2c061075f`.
Command 50 mesh replacement and command-49 flat-pattern clients remain
deferred. The command-52/53 donor files have SHA-256
`9491c080fcb56e54734ef21107ebf587aadcc9b58a7152547ec589efad91d3f3`
and
`f32206e4b48e72b9eb0ddfa0bfc3743766c09566b11ab52112693693eacdd3fc`.
All three builders remain experimental under `P3D-API-2` and do not send with
`RST.LIL $18`.

The complete `flight-input.inc` is also genuinely new, not a duplicate. Its
784 lines have SHA-256
`c12c952f41f4dfc25d50549f09cbd299a98eb7eb7742085a70a1228bf8f826eb`,
but its current shape is not a standalone API: it names application object,
ID, keyboard, initial-position, and ground globals; allocates a 77-byte global
state; and is single-instance and nonreentrant. Its step is not globally
transactional. Controls, rates, or object attitude may have changed before a
later arithmetic failure sets the sticky flag. A caller-owned extraction would
be new code needing its own qualification, so the full module is explicitly
deferred rather than mislabeled duplicate or copied verbatim.

That deferred model contains one specific ambiguity. The target
coordinated-yaw gate compares only the signed-Q8 airspeed high byte, activating
at 3072, while the host model and prose use the exact takeoff threshold 3200.
The inline block was neither vendored nor changed, and this note is not a claim
that any curated helper is wrong. The model's exact native-ADL24 position
integrator is likewise preserved as donor reference but omitted because it is
tied to the global state. Its preloaded `UDE` sign extension, byte loads into
`D:E`, unsuffixed three-byte position operations, and modulo-`2^24` position
wrap are intentional.

The complete `aircraft-view.inc`, KOAK camera-matrix `flight-backdrop.inc`, and
Berkeley aircraft-matrix antecedent have respective SHA-256 values
`b05ea34f01ee1cf91278716e24ece6b3c529f5ca30dbfbd1e70f24eb44c17a3c`,
`0d7952cc78daed69c390e087e3cee621129d856337d80b5d70139f34078f5899`,
and `524ab3131b3ec1a983667353d0fd9168b4b0540a2549beb04ad28689a5271832`.
They remain explicitly deferred policy modules. Terrain managers/providers and
regional streaming/LOD are larger subsystems and remain out of scope. The
repeated application-local camera sender is not copied: it is the same
transport pressure point already recorded under `P3D-API-1`, not a novel
flight helper requiring another duplicate implementation.

source credit and Cemetech URL for xeda112358 are now retained directly beside

ship under this candidate's root Unlicense. The complete lineage is in

records, with at least 10,000 deterministic records per implemented public
operation. The object VDU sender is intentionally excluded from the binary
harness because the byte stream provides no delivery acknowledgement.
