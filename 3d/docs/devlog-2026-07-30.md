# Development log — 2026-07-30

## Persistent object state and local motion

The integer 3D library now owns the complete eZ80-side state needed to drive a
write-only Pingo renderer. A packed 64-byte object contains resource IDs,
absolute world position, Pingo Euler cache, scale, local-to-world orientation,
local linear/angular velocity, angular residuals, and dirty flags.

`p3d_object_step16` applies intrinsic local rotation before transforming local
translation into world coordinates. `p3d_object_sync16` emits only dirty
absolute create, scale, rotation, and translation commands. This supports
transient move-object controls, persistent aircraft throttle, autonomous
rotation, and closed local-velocity orbits without asking the VDP to retain or
return authoritative state.

Fine interpolated sine/cosine consumes every periodic input bit while retaining
the compact generated table. Matrix composition uses a Q15-specific narrowing
path that clamps only the exact rounded `+/-32768` cardinal boundary to
`+/-32767`. Genuine larger overflow remains an error. This correction prevents
a held rotation from stalling when an orientation crosses a cardinal.

## Stateful integer camera aiming

A packed 36-byte camera state and the following public operations were added:

```text
p3d_camera_aim_at_point16
p3d_camera_aim_at_object16
p3d_camera_sync16
```

The integer look-at solver uses precision-reduced Cartesian-to-polar arithmetic
and fine angle interpolation. Callers must select one of two roll contracts:

1. `p3d_camera_roll_upright` retains a world-up horizon; and
2. `p3d_camera_roll_continuous` passes smoothly over a pole and may emerge
   inverted.

Upright tracking retains the last reliable yaw within a hysteretic pole cone.
This avoids gimbal-lock chatter when the target lies directly above or below
the camera. The retained fine-angle matrix remains the canonical camera
orientation; coarse Euler words are only the Pingo command representation.

## Regression coverage

The project now runs three emulator-backed suites plus a deterministic host
camera-smoothness oracle:

1. 60,596 scalar arithmetic records;
2. 71,834 transform records;
3. 251,337 matrix, object, packet, and camera records; and
4. deterministic fly-bys, distance/velocity scaling, half-turn seam,
   render-sampling, and near-pole smoothness checks.

Each public arithmetic, pose, camera, and packet-builder operation has at least
10,000 deterministic cases. Long held-control vectors cross every Q15
cardinal in both directions and specifically guard the former freeze.

## Pingo application qualification

The canonical `3d.inc` and generated table were copied byte-for-byte into
`pingoasm` application-local source trees. They now drive:

1. transient local-motion `moveobj-local`;
2. persistent-throttle `moveair-local`;
3. eZ80-owned tracking-camera updates; and
4. the six-object Earth Party stress scene.

The Jet controls, persistent throttle, smooth tracking camera, pole safeguards,
and former freeze path passed interactive emulator and physical-hardware
review. Earth Party demonstrated simultaneous controlled flight, a tilted
spinning Earth, and four phase-separated autonomous local-velocity orbits.
Those orbits close their complete retained state byte-for-byte after 128 fixed
simulation ticks.

The visually qualified emulator is the copied current-Pingo snapshot at
`pingoasm/emulators/tv-port-baseline`, not the mutable
`pingoasm/emulator` profile. The directory name is historical; the manifest
and VDP hash define its identity.
